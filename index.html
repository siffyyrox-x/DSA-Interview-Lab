Topic 01 · ~3h · Day 1

Python for DSA & Online Tests

Use Python deliberately: know which operations are cheap, which copy data, and how online-test input differs from LeetCode method calls.

1.1The idea

In plain English

Think of Python as a workshop. A list, dict, set, deque and heap are different tools; using the wrong one can turn a clean O(n) idea into an O(n²) program.

  • Lists are dynamic arrays: append is amortized O(1), indexing O(1), but inserting/removing near the front is O(n). Slices create copies proportional to the slice length.
  • Strings are immutable. Build many pieces in a list and use "".join(parts) instead of repeated concatenation in a long loop.
  • dict/set provide average O(1) membership; keys must be hashable. Counter and defaultdict remove bookkeeping noise.
  • Use enumerate, zip, sorted(key=...), any/all, min/max with key, and tuple ordering. heapq and bisect are standard interview tools.
  • Python floor division and modulo follow floor semantics for negatives: -3//2 == -2 and -3%2 == 1.
  • Never write [[0]*m]*n for an editable matrix: every row points at the same inner list. Avoid mutable default arguments such as def f(a=[]).
  • For deep recursion, an iterative stack is often safer; sys.setrecursionlimit can help but does not change algorithmic space.
  • LeetCode usually calls class Solution methods; online judges often require stdin parsing, multiple test cases and fast output.

Topic 02 · ~3h · Day 2

Big-O & Complexity

Complexity is how you reject a solution before it times out. Learn to estimate time, space, amortized cost and recursion growth from constraints.

2.1The idea

In plain English

Imagine the input doubles. If the work doubles, that is linear. If it quadruples, think quadratic. If it adds one extra step, think logarithmic.

  • Ignore constant factors for asymptotic analysis, but do not ignore nested input dimensions: O(rows*cols) is not O(n) unless n means all cells.
  • Consecutive loops add; nested dependent loops often multiply. Two pointers can look nested yet remain O(n) when each pointer only moves forward.
  • Amortized analysis explains dynamic-array append: an occasional resize is expensive, but spread over many appends the average is O(1).
  • Space includes auxiliary arrays, hash maps, recursion depth and sometimes the output if the interviewer asks for total memory.
  • A recursion tree multiplies branching factor across depth. Naive Fibonacci is exponential because the same subproblems are recomputed.
  • Constraint heuristics: n≈20 may allow 2^n; n≈10³ may allow n²; n≈10⁵ usually wants n log n or n; n≈10⁶ often wants close to linear.

Topic 03 · ~9h · Day 3–5

Arrays, Strings & Prefix Sums

Master the default interview container: traversal, in-place mutation, prefix techniques, Kadane, matrix transforms and string counting.

3.1The idea

In plain English

An array is a row of labeled lockers. Indexing jumps directly to a locker; insertion in the middle forces everything after it to shift.

  • Dynamic arrays give O(1) indexing and amortized O(1) append. In-place edits use read/write pointers or swaps to avoid extra arrays.
  • Prefix sums store cumulative totals: range(l,r)=pref[r+1]-pref[l]. 2D prefix sums answer rectangle queries with inclusion–exclusion. Difference arrays invert the idea for many range updates.
  • Kadane keeps the best subarray ending here; if the previous sum hurts the next element, restart. Prefix/suffix products solve product-except-self without division.
  • Boyer–Moore majority voting cancels different values and leaves a candidate; if the problem does not guarantee a majority, verify it afterward.
  • Matrix patterns: transpose + reverse for rotation, boundary shrink for spiral, marker rows/columns for set-zeroes.
  • String interview patterns are often counting/normalization: anagrams, reverse words, longest common prefix, character frequencies and two pointers.

3.2Python toolkit

Use these idioms as a starting point, then adapt them to the problem's exact constraints and return format.

# 1D prefix sums
pref = [0]
for x in nums:
    pref.append(pref[-1] + x)

def range_sum(l, r):
    return pref[r + 1] - pref[l]

# Kadane
best = cur = nums[0]
for x in nums[1:]:
    cur = max(x, cur + x)
    best = max(best, cur)

3.5Worked example: from brute force to the pattern

Brute-force instinct

Enumerating every subarray and summing it is O(n³), or O(n²) with prefix sums. Kadane observes that only the best sum ending at i-1 matters for extending into i, reducing the state to one number and the time to O(n).

The optimized approach follows the invariant taught above and removes repeated work or impossible candidates.

How to say it in an interview: "At each index I either start a new subarray here or extend the best one ending immediately before it; that local recurrence is sufficient."

Topic 04 · ~6h · Day 6–7

Hashing: dict, set & Counter

Hashing converts repeated search into direct lookup. Learn complements, frequencies, grouping, prefix-count maps and O(1) design patterns.

4.1The idea

In plain English

A hash table is a wall of mailboxes. The hash function chooses the mailbox; collisions mean several letters share a box, so the key is still checked.

  • dict maps keys to values; set stores only keys. Average lookup/insert/delete is O(1), with O(n) worst case theoretically.
  • Hashable keys must have stable hashes: integers, strings and tuples of hashables work; lists and dicts do not.
  • Complement lookup solves Two Sum: for x, ask whether target-x was seen. Frequency maps power anagrams, top-k and counting.
  • Group-by problems need a canonical key: sorted string O(k log k), or a 26-count tuple O(k) for lowercase letters.
  • Prefix-sum + hashmap counts subarrays: if current prefix is p, a previous p-k creates a sum-k subarray.
  • Last-seen index maps support longest substring/window problems; sets support consecutive-sequence expansion.
  • O(1) design questions often combine structures, e.g. a hash map plus array or doubly linked list.

4.2Python toolkit

Use these idioms as a starting point, then adapt them to the problem's exact constraints and return format.

4.5Worked example: from brute force to the pattern

Brute-force instinct

A brute-force O(n²) enumeration can compute every range. Using prefix sums, a subarray ending now sums to k exactly when an earlier prefix equals current-k; a frequency map counts all such earlier prefixes in O(1) average time.

Pattern-level solution

The optimized approach follows the invariant taught above and removes repeated work or impossible candidates.

How to say it in an interview: "I store how many times each prefix sum occurred. For current prefix p, every previous p-k creates one valid subarray ending here."

5.1The idea

In plain English

Put one finger on each end of a sorted row. If the sum is too small move the left finger to a larger value; if too large move the right finger to a smaller value.

  • Opposite-end pointers exploit sorted order for pair sums, palindrome checks, water/container problems and shrinking intervals.
  • Same-direction read/write pointers compact arrays in place and remove duplicates without repeated shifting.
  • Two-sequence pointers merge sorted arrays or test subsequences in O(n+m).

Sliding Window

Sliding windows solve contiguous-subarray and substring problems by maintaining exactly the information inside a moving range.

6.1The idea

In plain English

Imagine a camera frame sliding over a long banner. Instead of recounting everything visible after each move, subtract what leaves and add what enters.

  • Fixed windows keep exact length k: initialize the first window, then add right and remove left on each slide.
  • Variable windows expand right until a rule breaks, then shrink left until valid again. Each index enters/leaves once, so O(n).

Linked Lists

Linked lists test pointer discipline: dummy heads, reversal, fast/slow detection, merging, reordering and hash-map + doubly-linked-list design.

9.1The idea

In plain English

Think of train cars connected by couplers. To reorder the train you change links between cars; there is no direct jump to the 50th car.

  • A dummy head removes special cases when the real head can change. Return dummy.next.
  • Iterative reversal stores next before overwriting curr.next. Recursive reversal returns the new head then flips one edge.
  • Fast/slow pointers find the middle and detect cycles. Floyd cycle-start proof resets one pointer to head after the first meeting.
  • Gap pointers remove nth-from-end: move fast n steps ahead, then advance both until fast reaches the end.
  • Merge two sorted lists by attaching the smaller current node to a tail pointer.
  • Reorder list = find middle, reverse second half, alternate merge. Palindrome = compare first half against reversed second half.
  • LRU Cache combines O(1) hashmap lookup with a doubly linked list that moves recently used nodes to one end.

Recursion makes tree-shaped reasoning concise. Learn base cases, call-stack cost, memoization, fast exponentiation and how to convert recursion to an explicit stack.

10.1The idea

In plain English

A recursive function delegates a smaller version of the same job to a future copy of itself, then finishes its own work when that copy returns.

  • Every recursion needs progress toward a base case. The "leap of faith" is to assume the smaller call works, then combine.
  • The call stack stores local variables and return locations; maximum recursion depth therefore contributes to space complexity.
  • Naive Fibonacci repeats subproblems; functools.cache converts the recursion tree into a DAG of unique states.
  • Fast power halves the exponent: x^n = (x^(n//2))², with one extra x for odd n, giving O(log n).
  • Avoid recursive slicing like solve(a[1:]) when indexes can avoid O(n) copies.
  • Any DFS recursion can usually be converted to an explicit stack that stores the same state manually.

11.1The idea

In plain English

  • The universal template is choose → explore → unchoose. Save path[:] or tuple(path) because path itself keeps changing.

  • Word Search marks a grid cell during the path and restores it after recursion. N-Queens tracks occupied columns and diagonals in sets.

Sorting

Sorting is both a tool and a family of interview algorithms. Understand stability, keys, divide-and-conquer, partitioning and selection.

12.1The idea

In plain English

Trees combine recursion, stacks and queues. Learn DFS/BFS, bottom-up returns, global/nonlocal answers, reconstruction and serialization.

14.1The idea

In plain English

A tree is an organization chart. To answer a question about the CEO node, you often first ask each department subtree for a summary, then combine the summaries.

  • Vocabulary: root, parent, child, leaf, depth, height, subtree. LeetCode level-order arrays use None for missing children.

In plain English

Heaps maintain the next smallest/largest priority without fully sorting. Learn heapq, top-k, k-way merge and two-heap streaming median.

16.1The idea

In plain English

A heap is a tournament bracket where the winner is always at the top. You do not know the complete ranking, but you can quickly remove the current winner and repair the bracket.

  • A binary heap is an array-backed complete tree. Parent=(i-1)//2; children=2i+1,2i+2. Sift-up/down restores heap order.

  • Merge k sorted lists pushes one head per list, then replaces it with the next node from that list.
  • Median of a stream uses max-heap lower half + min-heap upper half, rebalanced so sizes differ by at most one.

Graphs unify networks, grids, dependencies and connectivity. Master representations, traversal, components, topological order, union-find and bipartite reasoning.

17.1The idea

In plain English

A graph is a city map: intersections are vertices and roads are edges. BFS explores by distance rings; DFS follows one road as far as possible before backtracking.

  • Build adjacency lists from edge lists. For undirected edges add both directions. Complexity is O(V+E) for adjacency-list traversal.
  • BFS uses deque and marks visited on enqueue. DFS uses recursion or explicit stack. Repeating a traversal from each unseen node counts connected components.
  • Grid problems are implicit graphs: each cell has up to four/eight neighbours. Number of Islands marks a whole component; Flood Fill recolors one.
  • Multi-source BFS enqueues all sources at distance 0, useful for nearest-source distances such as rotting oranges.
  • Directed cycle detection can use DFS coloring (unvisited/visiting/done) or Kahn topological sort: if processed count < V, a cycle exists.
  • Union-find stores parent and rank/size. Path compression + union by rank gives nearly constant amortized operations and is excellent for connectivity under edge additions.
  • Bipartite check two-colors each component; an edge between equal colors proves failure. Clone Graph needs a map old node → cloned node.

Shortest Paths & Minimum Spanning Trees

Choose path algorithms by edge assumptions: Dijkstra, Bellman–Ford, Floyd–Warshall, 0-1 BFS, Kruskal and Prim.

18.1The idea

In plain English

Different road maps need different planners. If every road is nonnegative, Dijkstra works; negative tolls require a method that allows later corrections.

  • Dijkstra repeatedly extracts the node with smallest known distance from a heap. Lazy deletion skips heap entries whose distance is stale.
  • Bellman–Ford relaxes all edges repeatedly and handles negative weights; bounded-edge variants model "at most K stops" by controlling relaxation rounds.
  • Floyd–Warshall uses dp[k][i][j] to allow intermediate nodes from a growing prefix, giving O(V³) all-pairs shortest paths.
  • 0-1 BFS uses a deque when weights are only 0 or 1: zero-weight moves go left, one-weight moves go right.
  • Kruskal sorts edges and uses union-find to add the cheapest edge that does not create a cycle. Prim grows one tree using a frontier heap.
  • Path reconstruction stores predecessor when a relaxation improves distance, then walks parents backward from target.

18.2Python toolkit

Use these idioms as a starting point, then adapt them to the problem's exact constraints and return format.

import heapq

def dijkstra(g, src):
    dist = {src: 0}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]: continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

Greedy algorithms commit to a locally best choice only when an exchange/proof argument makes that choice safe. Interval problems are the most reusable form.

19.1The idea

In plain English

Dynamic Programming

Dynamic programming is the biggest pattern family: define states and transitions, then cache or tabulate them. Learn 1D, knapsack, strings, grids and interval-style thinking.

20.1The idea

In plain English

DP is filling a workbook where each answer may reuse answers from earlier pages. The hard part is deciding what one cell means; after that, the recurrence and order follow.

  • The five-part framework: state (what does dp[...] mean?), transition, base cases, computation order, answer location.

Tries (Prefix Trees)

Tries index strings by prefix, making search and autocomplete depend on word length rather than the total number of stored words.

21.1The idea

In plain English

A trie is a dictionary where words sharing the same beginning literally share the same hallway until their letters diverge.

  • A TrieNode stores children mapping character→node and is_end to distinguish complete words.
  • Insert walks/creates one node per character. Search requires every character and a terminal flag. startsWith requires only the path.
  • A compact Python version can use nested dicts with a special terminal marker.
  • Autocomplete walks to the prefix node then DFS/BFS collects terminal descendants, often stopping after k suggestions.
  • Wildcard "." search branches across all children at that position, so worst-case can grow exponentially in the number of wildcards.
  • Word Search II combines trie prefix pruning with board DFS so searches for many words share work.

Do not jump directly to memorized code. For each problem, state the brute force and why it fails the constraints, identify the structural signal, state an invariant, then implement. This makes the solution adaptable if the interviewer changes the requirement.

Pattern-level solution

The optimized approach follows the invariant taught above and removes repeated work or impossible candidates.

How to say it in an interview: "I’ll first confirm constraints, give the simplest correct approach, then improve the bottleneck. I’ll state the invariant before coding so we can verify correctness as we go."
